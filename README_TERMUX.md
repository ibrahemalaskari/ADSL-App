# تشغيل المشروع وتجربته في Termux — خطوة بخطوة

نفّذ كل أمر في Termux بالترتيب. بعد كل خطوة تأكد من «المتوقع» قبل الانتقال للتي بعدها. إن اختلف ما ظهر لك فتوقف وأرسل لي نص الشاشة.

## 0) قبل البدء
- الهاتف على **نفس شبكة الراوتر** (واي فاي الراوتر).
- اعرف عنوان الراوتر (عادةً `192.168.88.1`). تجده في إعدادات واي فاي الهاتف باسم «البوابة/Gateway».
- لا حاجة للراوتر في الخطوات 1 إلى 7. هي تجهيز واختبارات على الهاتف فقط.

## 1) تثبيت Termux
ثبّته من **F-Droid** أو من **GitHub Releases** (صفحة termux/termux-app). لا تخلط مصدرين (F-Droid ثم GitHub) لأن التوقيعات تختلف. نسخة Google Play موجودة لكنها مبنية من مستودع منفصل وما زالت تجريبية، فالأفضل تجنبها لهذا المشروع.

## 2) أول تشغيل
افتح Termux واكتب:
```
pkg update
```
- إن سألك سؤالاً بنعم/لا (`Y/n`) أو عن ملفات إعداد، اضغط **Enter** (الخيار الافتراضي).
- إن ظهر خطأ اتصال بالمستودعات: اكتب `termux-change-repo` واختر أي مرآة ثم أعد الأمر.

## 3) تثبيت Node
```
pkg install nodejs unzip
node --version
```
المتوقع: Node.js **22.5 أو أحدث** (مثل `v22.16.0`) لأن المشروع يستخدم `node:sqlite`.

## 4) السماح بالوصول لملفات الهاتف
```
termux-setup-storage
```
اضغط **السماح** في نافذة الإذن. بعدها يظهر مجلد `~/storage/downloads` (هو مجلد «التنزيلات» في الهاتف).

## 5) نقل المشروع
نزّل `adsl-app.zip` من المحادثة (يذهب إلى التنزيلات)، ثم:
```
cd ~
ls ~/storage/downloads | grep adsl
```
إن كان اسم الملف مختلفاً (مثل `adsl-app (1).zip`) فاستعمل اسمه في الأمر التالي:
```
cp ~/storage/downloads/adsl-app.zip ~/
unzip -o adsl-app.zip
cd adsl-app
ls
```
المتوقع: ترى `core` و`bridge` و`www` و`test` و`tools` و`package.json`.

## 6) اختبارات الوحدة
```
npm test
```
المتوقع في آخر الشاشة: جميع الاختبارات ناجحة، ولا يوجد فشل. في الإصدار 0.8.0 بلغ العدد 211 اختباراً. هذه اختبارات منطق وبروتوكول على راوتر وهمي وليست اختباراً على RouterOS حقيقي.

## 7) تجربة Excel (اختيارية، لا تحتاج الراوتر)
انسخ ملفك الحقيقي (استعملنا `*` لتجنب كتابة الاسم العربي كاملاً):
```
cp ~/storage/downloads/استهلاك_الرصيد*.xlsx data.xlsx
node tools/excel-cli.mjs import data.xlsx state.json
```
- يطبع الأشهر التي وجدها وعدد الأيام والفوارق اليدوية وأي تنبيهات، ويحفظ النتيجة في `state.json`. الملف الأصلي لا يُعدَّل أبداً.
- أعد نفس الأمر مرتين: في الثانية يجب أن يظهر `أيام جديدة 0` (لا تكرار).

للتصدير (يسألك عن الشهر):
```
node tools/excel-cli.mjs export data.xlsx state.json out.xlsx
cp out.xlsx ~/storage/downloads/
```
افتح `out.xlsx` من التنزيلات في Excel أو WPS وتأكد أن الأرقام والصيغ تظهر، وأرسل لي ما تراه. أول مرة تفتحه قد تحتاج أن يحسب البرنامج الصيغ.

## 8) تفعيل API في الراوتر (يدوياً، أنت من يفعله)
التطبيق لا يستطيع تفعيل API بنفسه. من Winbox: `IP` ثم `Services`، حدّد سطر `api` واضغط علامة ✔ للتفعيل. أو من الطرفية:
```
/ip service print
/ip service enable api
```
تأكد أن المنفذ `8728` وأن سطر `api` بلا حرف `X`. وإن كان في عمود `Available From` عنوان، فيجب أن يشمل عنوان هاتفك. **أوقفه بعد انتهاء التجربة:**
```
/ip service disable api
```

## 9) تشغيل الجسر وفتح صفحة التجربة
في Termux:
```
cd ~/adsl-app
node bridge/server.js
```
المتوقع: `الجسر يعمل: http://127.0.0.1:8787/dev.html`. **اترك هذه الجلسة تعمل.** ولمنع أندرويد من إيقافها اسحب شريط إشعار Termux واضغط **Acquire wakelock**.

افتح متصفح الهاتف واذهب إلى:
```
http://127.0.0.1:8787/dev.html
```
- أدخل عنوان الراوتر واسم المستخدم وكلمة المرور، والمنفذ `8728`.
- اضغط **اختبار الاتصال**، ثم **اكتشاف الواجهات**، ثم **قراءة وتسجيل**، وانتظر دقيقة أو أكثر (يفضّل أن يحصل استهلاك على الخط) واضغط **قراءة وتسجيل** مرة ثانية.
- الأداة تقرأ فقط ولا تغيّر أي إعداد في الراوتر، وكلمة المرور لا تُحفظ.

### حساب بصلاحيات قراءة فقط (اختياري، يُنصح به)
نفّذه أنت على الراوتر إن رغبت. لم أجرّبه على راوتر، فتأكد من الصياغة في إصدارك:
```
/user group add name=adsl-read policy=read,api
/user add name=adsl group=adsl-read password=كلمة_مرور_قوية
/ip service set api address=192.168.88.0/24
```
الأمر الأخير يقصر API على شبكتك المحلية (عدّل النطاق حسب شبكتك). الحساب الجديد قد لا ينجح تسجيل دخوله إن نقصت صلاحية، فجرّب أولاً بحسابك المعتاد إن أردت حصر المشكلة.

## 10) إيقاف كل شيء
- في Termux اضغط `Ctrl+C` لإيقاف الجسر (في لوحة Termux الإضافية زر CTRL، أو Volume Down مع C).
- في الراوتر: `/ip service disable api`.

## 11) ما أرجو أن ترسله لي
- من الخطوة 6: آخر 4 أسطر (`# tests` و`# pass` و`# fail`).
- من الخطوة 7: ما طبعه الأمر `import`، وهل فتح `out.xlsx` وأظهر الأرقام والصيغ.
- من «اختبار الاتصال»: الإصدار والموديل وحالة API.
- من «اكتشاف الواجهات»: لقطة للجدول (أخفِ ما تراه حساساً).
- من «قراءة وتسجيل»: لقطة بعد القراءة الثانية.
- من الخطوة 13 (فحص اليوزر مانجر): نص التقرير كاملاً كما طبعته الأداة.
- نص أي رسالة خطأ كما هي.

## 12) إن تعثّرت
| ما يظهر | السبب المرجّح |
|---|---|
| `pkg: command not found` أو أخطاء مستودعات | نسخة Termux قديمة أو مصدر خاطئ، أو جرّب `termux-change-repo` |
| `ls ~/storage` فارغ أو غير موجود | لم تمنح إذن التخزين، أعد `termux-setup-storage` |
| اختبارات `npm test` فشلت | أرسل الأسطر التي تبدأ بـ `not ok` |
| الصفحة لا تفتح | الجسر ليس شغّالاً (الخطوة 9) أو أُغلقت جلسة Termux |
| «API معطل» أو رفض اتصال | الخدمة غير مفعّلة، أو المنفذ ليس 8728، أو العنوان المسموح لا يشمل الهاتف |
| «انتهت المهلة» | العنوان خاطئ أو الهاتف ليس على شبكة الراوتر |
| «بيانات الدخول» أو «الصلاحيات» | اسم المستخدم أو كلمة المرور خاطئة، أو سياسة المستخدم تنقصها `api` أو `read` |

## 13) فحص اليوزر مانجر (قراءة فقط)
الهدف: معرفة هل يعرض الراوتر اليوزر مانجر عبر API في إصدارك، وما أسماء حقوله، وكم مستخدماً في كل باقة، وما قيود كل باقة. الأداة تُرسل أوامر `print` فقط ولا تغيّر شيئاً في الراوتر، ولا تحتاج الجسر.

1. فعّل API يدوياً كما في الخطوة 8 (وقيّده بعنوان هاتفك أو شبكتك).
2. في Termux (غيّر العنوان واسم المستخدم):
```
cd ~/adsl-app
node tools/um-probe.mjs 192.168.88.1 admin
```
3. ستُسأل عن كلمة المرور، **ولن تظهر وأنت تكتبها**. اكتبها واضغط Enter.
4. يُطبع التقرير ويُحفظ في ملف `um-probe-<الوقت>.txt` في المجلد نفسه. أرسل لي نصه كما هو (أو الملف: `cp um-probe-*.txt ~/storage/downloads/`).
5. **عطّل API فوراً:** `/ip service disable api`

ما الذي تقرؤه الأداة:
- أولاً: العدد في كل قائمة، دون أي حقل حساس.
- ثم **عيّنة من 5 مستخدمين كحد أقصى** بكل حقولهم، لاكتشاف أسماء الحقول فقط. هذه الصفوف فيها كلمات مرور الكروت وتمر على شبكتك المحلية بلا تشفير (كأي اتصال API على 8728)، وتُهمَل قيمها في الذاكرة ولا تُعرض ولا تُحفظ.
- ثم إحصاءات على حقول محددة فقط (الباقة والاستهلاك المستخدم وآخر ظهور وغيرها)، بطلب هذه الحقول صراحةً دون كلمات المرور.
- الباقات والقيود وربطهما تُعرض بقيمها كاملة (هي إعدادات، ليست بيانات كروت).
- لا يُقرأ سجل العملاء ولا قائمة الرواتر ولا المدفوعات (فيها كلمات مرور وأسرار).

حالات خاصة:
- «تعذّر أخذ عيّنة» في قائمة المستخدمين: أعد الأمر بخيار `--full-sample`. يقرأ كل الصفوف بكل حقولها (وفيها كل كلمات المرور تمر على الشبكة المحلية) ويُهمل القيم في الذاكرة. لا تستعمله إلا إن فشل الوضع العادي.
- «لا يعرف هذا المسار»: الحزمة غير مثبّتة أو أن API لا يعرض القائمة في هذا الإصدار. الأداة لا تفرّق بينهما، وأرسل لي النص كما هو.
- «الصلاحيات»: حسابك لا يكفي لقراءة القائمة. لا تغيّر صلاحياته قبل أن تقرر معي.
- الحماية الآلية تمنع الاتصال بعناوين غير الشبكات الخاصة وبمنافذ غير 8728 و8729. وAPI-SSL غير مدعوم في هذه الأداة (لم يُختبر).

## 14) قراءة الكروت: يوم الفتح والرصيد المستهلك L (قراءة فقط)
الهدف: لكل يوم، عدد الكروت المفتوحة فيه لكل فئة (100/200/250/500/1000) ومجموع استهلاكها (العمود `L`)، مع قاعدة التثبيت. تُرسل الأداة أوامر `print` فقط ولا تغيّر شيئاً في الراوتر، ولا تحتاج الجسر.

0. حدّث الحزمة (فك الأحدث فوق القديم) وشغّل `npm test`؛ يجب أن يظهر `# pass 168`.
   **(ج15) مهم:** أول مرة بعد هذا التحديث احذف ملف الحالة القديم ثم شغّل الأداة **في اليوم نفسه** (قبل منتصف الليل بتوقيت الراوتر)، وإلا ضاع اليوم السابق: `rm cards-state.json` ثم الأمر في الخطوة 2 مع `--state cards-state.json`. السبب: الملف القديم يحوي أياماً قديمة (قبل المعيار الجديد).
1. فعّل API يدوياً وقيّده بعنوانك (الخطوة 8).
2. في Termux:
```
cd ~/adsl-app
node tools/cards-read.mjs 192.168.88.1 admin --days 30
```
3. اكتب كلمة المرور (لا تظهر). يُطبع التقرير ويُحفظ في `cards-read-<الوقت>.txt`. أرسل نصه كما هو. ثم **عطّل API:** `/ip service disable api`

ما يعرضه التقرير: لكل يوم: عدد الكروت لكل فئة، و`L` بالجيجا والميجا. **الأيام القديمة تُخفى** (قرارك): لا يُقبل يوم جديد عمره أكبر من يوم واحد قبل يوم القراءة (اليوم والأمس فقط، قرارك في ج15)، ولا يوم كان فيه كروت منتهية الصلاحية قبل أول قراءة له (يبدأ ناقصاً). هذه الأيام لا تُعرض ولا تُخزَّن، ويظهر سطر «أيام قديمة مخفية: N». الأيام المخزّنة سابقاً تبقى تُحدَّث وتُثبَّت مهما كبر عمرها. فيجب تشغيل الأداة يومياً (مزامنة فاتت يومين تعني ضياع ذلك اليوم). (بلا `--state` لا يُعرف أي يوم كان مكتملاً عند أول قراءة، فتُخفى كل الأيام التي فيها كروت منتهية؛ استعمل `--state` ليظهر اليوم الذي بدأ مكتملاً ثم انتهى بعض كروته.) ثم **فحص الاتساق**: لكل باقة أعلى استهلاك مقابل حدّها؛ إن زادت النسبة كثيراً عن 1 فاخبرني. ثم التنبيهات.

**(ج14) أسطر التشخيص:** بعد سطر الأعمدة يطبع التقرير الآن «حقل اسم المستخدم المستعمل» و«حقول وصلت في صفوف المستخدمين» (أسماء الحقول وعدد الصفوف التي فيها قيمة، بلا أي قيم). إن ظهر تنبيه «لا مستخدم واحد وصل له حقل actual-profile» فشغّل مباشرة بعد القراءة، وفي جلسة تفعيل API نفسها: `node tools/um-probe.mjs 192.168.88.1 admin` وأرسل التقريرين معاً (للمقارنة بين ما يصل للقارئ وما يصل للفحص).

تجربة قاعدة التثبيت يوماً بعد يوم: أضف `--state cards-state.json`. في أول مرة يُسجَّل اليوم «مؤقتاً»، وفي مزامنة يوم لاحق إن طابق الرقم السابق يظهر «ثُبّت الآن»، وبعدها «مثبّت» ولا تتغيّر قيمته. وإن **نقص** الرقم بعد انتهاء اليوم (انتهى كرت واختفى) يظهر «نقص الرقم: ثُبّت على أكبر قيمة رُصدت» (قرارك)، فيبقى الأكبر ولا يبقى اليوم مؤقتاً. نقصان في يوم الكروت نفسه لا يُثبَّت لأن اليوم لم ينتهِ. الملف أرقام فقط. (حذفه يعيد التجربة من الصفر.)

ما تقرؤه الأداة: اسم المستخدم (في الذاكرة فقط لربط الجلسات بالمستخدمين، ولا يُعرض ولا يُحفظ) والباقة الفعلية والتنزيل والرفع المستهلكان، ومن الجلسات: المستخدم ووقت البدء. لا تُطلب كلمات المرور ولا العناوين. إن ظهر «لم يُعثر على حقل اسم المستخدم» فأرسل لي الرسالة كما هي.

## 15) النسخ الاحتياطي والاستعادة (ج17، لا تحتاج الراوتر ولا الشبكة)
الهدف: حفظ نسخة من ملف الحالة (مثل `cards-state.json`) والتحقق منها واستعادتها. الأداة **لا تعدّل ملف الحالة ولا تستبدل ملفاً موجوداً**؛ تكتب ملفاً جديداً دائماً.

0. حدّث الحزمة وشغّل `npm test`؛ يجب أن يظهر `# pass 168`.
1. نسخة جديدة (يُحفظ الملف باسم يحوي الوقت، ويُقرأ بعد كتابته للتحقق منه):
```
cd ~/adsl-app
node tools/backup-cli.mjs create cards-state.json
```
2. فحص نسخة (يتحقق من سلامتها ويعرض ملخصها، بلا استعادة):
```
node tools/backup-cli.mjs inspect adsl-backup-20261123-120000.json
```
3. استعادة (النتيجة في ملف جديد، فراجعها ثم انقلها أنت فوق الأصل إن أردت):
```
node tools/backup-cli.mjs restore cards-state.json adsl-backup-20261123-120000.json --out restored.json
```
   - الوضع الافتراضي **دمج**: لا يُكتب فوق قيمة موجودة ولا يُحذف يوم، وتُعرض التعارضات (بقيت قيمة الحالة الحالية).
   - `--mode replace`: استبدال كامل بالنسخة، ويعرض عدد الأيام التي ستضيع من الحالة الحالية. لا يُنفَّذ إلا إن كتبته صراحةً.

ملاحظات: ملفات `adsl-backup-*.json` لا تُرفع إلى GitHub (مستثناة في `.gitignore`) لأنها تحوي بياناتك. النسخة لا تحوي كلمات مرور ولا أسماء مستخدمي الكروت، وتُرفض إن وُجد فيها مفتاح اسمه password أو secret أو token. مجموع التحقق يكشف التلف والبتر العرضيين فقط، لا التلاعب المقصود. إن فشل أي أمر يُطبع الرمز (مثل `BACKUP_CHECKSUM`)؛ أرسله لي كما هو.

## أمان الجسر
- يستمع على `127.0.0.1` فقط، ولا يتصل إلا بعناوين الشبكات الخاصة وعلى المنفذين 8728 و8729.
- بروتوكول API على 8728 غير مشفّر، وكلمة المرور تمر على شبكتك المحلية بلا تشفير. استعمل شبكة موثوقة.


## 16) مزامنة كروت اليوزر مانجر داخل واجهة التطبيق (ج22، الإصدار 0.6.3)

هذه الخطوة تستخدم زر المزامنة داخل الصفحة نفسها، ولا تستبدل أداة `cards-read.mjs` التي تبقى مفيدة للمقارنة والتقارير.

1. فكّ حزمة `adsl-app-0.6.3.zip` فوق مجلد المشروع، أو استخرجها في مجلد جديد. إن كنت تحدّث نسخة موجودة:
```
cd ~
unzip -o ~/storage/downloads/adsl-app-0.6.3.zip -d ~/adsl-app
cd ~/adsl-app
npm test
```
المتوقع: `# pass 168` و`# fail 0`.
2. تأكد أن الهاتف على شبكة الراوتر نفسها. قيّد خدمة API على عنوان الهاتف أو شبكته المحلية، ثم فعّلها يدوياً من الراوتر. لا تفتحها للإنترنت العام.
3. شغّل الجسر في Termux واتركه مفتوحاً:
```
cd ~/adsl-app
node bridge/server.js
```
المتوقع: `الجسر يعمل: http://127.0.0.1:8787/dev.html`.
4. في متصفح الهاتف افتح صفحة التطبيق:
```
http://127.0.0.1:8787/adsl-app.html
```
انتقل إلى **أدوات ← اتصال الراوتر ومزامنة الكروت**. أدخل عنوان الراوتر، والمنفذ `8728`، واسم المستخدم وكلمة المرور. اضغط **قراءة الكروت ومزامنتها**.

- زر مزامنة الراوتر في الواجهة يحفظ في SQLite بعد إتمام الترحيل؛ عند بدء الصفحة تُحمّل قراءات الراوتر من SQLite.
- تُعرض حالة «مؤقت» و«مثبّت» ووقت آخر مزامنة، ويظل سجل العمليات متاحاً في «أدوات».
- «أدوات ← النسخ الاحتياطي والاستعادة»: ملف JSON مع CRC-32، والدمج هو الخيار الافتراضي. الاستبدال يحتاج تأكيداً إضافياً. الملف لا يتضمن كلمات المرور أو بيانات دخول الراوتر.
- تشديد التحقق من تواريخ الأيام: لا تُقبل التواريخ المستحيلة مثل 31 فبراير في تخزين الأرصدة أو قراءتها أو مسحها.
- توحيد رقم الإصدار إلى 0.7.8 في بيانات الحزمة والنسخ الاحتياطية.

### اختبار القبول على الهاتف

1. تأكد أن «أدوات» تعرض أن ترحيل SQLite مكتمل.
2. نفّذ مزامنة واحدة من الراوتر بعد تفعيل API يدوياً وتقييده بعنوان جهازك.
3. تأكد أن نتيجة المزامنة تقول إنها حُفظت في SQLite.
4. أغلق الصفحة وافتحها مجدداً؛ يجب أن تعود الأيام وحالة «مؤقت/مثبّت» وآخر مزامنة.
5. أنشئ نسخة احتياطية من «أدوات»، وتأكد من تنزيل ملف `adsl-backup-*.json`.
6. اختبر الاستعادة بالدمج على نسخة من البيانات أو بعد أخذ نسخة احتياطية أخرى. لا تختبر «الاستبدال» على بياناتك الوحيدة.
7. عطّل API فور الانتهاء من الاختبار على الراوتر:

```routeros
/ip service disable api
```

**نتيجة التحقق المحلي للإصدار 0.7.8:** 201 اختباراً ناجحاً و0 فشل على Node.js 22.16.0، وفحص صياغة JavaScript للواجهة والجسر والوحدات الأساسية.

**حدود التحقق:** الاختبارات المحلية لا تثبت بعد نجاح واجهة الويب على هاتف Termux ولا القراءة الحية على الراوتر؛ يلزم اختبار القبول أعلاه. قاعدة بياناتك الفعلية لم تكن ضمن ملف المراجعة، لذلك لم تُفحص بياناتها ولم تُعدّل. لا تُرسل كلمة مرور الراوتر أو أسماء مستخدمي الكروت في المحادثة.

## 29. تحسين مزامنة أرشيف المبيعات (0.8.2)

أصبحت نتيجة مزامنة المبيعات تميّز السجلات الجديدة (`inserted`) والسجلات التي تغيرت بياناتها فعلاً (`updated`) والسجلات المطابقة دون تغيير (`unchanged`). يسهّل ذلك متابعة المزامنة المتكررة من User Manager دون اعتبار كل إعادة قراءة تحديثاً فعلياً. لا تحذف المزامنة سجلات لم تعد تظهر في قراءة الراوتر، لأن اختفاء الجلسات من الراوتر لا يثبت أن سجل البيع غير صحيح.

## قراءة عدادات VLAN والواجهات (المخطط 5)

أضيفت شاشة قراءة عدادات الواجهات التراكمية من MikroTik RouterOS v6:

1. شغّل الجسر المحلي كالمعتاد ثم افتح التطبيق عبر `http://127.0.0.1:8787/adsl-app.html`.
2. افتح تبويب **الفيلانات** ثم **قراءة عدادات الراوتر الآن**.
3. أدخل عنوان الراوتر ومنفذ API واسم المستخدم وكلمة المرور في نافذة الاتصال. تُستخدم كلمة المرور في الذاكرة أثناء القراءة فقط ولا تُحفظ في قاعدة البيانات أو السجل.
4. نفّذ القراءة مرة أولى لتسجيل نقطة الأساس، ثم نفّذ قراءة لاحقة بعد مرور فترة استخدام حتى يحسب التطبيق الفرق بين RX/TX.
5. تُجمع الواجهات ذات `vlan-id` من 1 إلى 6 بحسب رقم VLAN الفعلي الذي يعيده الراوتر. الواجهة التي لا تحمل رقم VLAN معروفاً لا تُنسب تلقائياً إلى أحد العملاء.

تُحفظ كل قراءة في جدول `interface_counter_readings` في SQLite، وتُرفض القراءة الفارغة أو الأقدم زمنياً، ولا تتكرر القراءة ذات الطابع الزمني نفسه. أول قراءة لا تنتج استهلاكاً. وعند اكتشاف إعادة تشغيل الراوتر أو انخفاض عداد RX/TX تُستبعد الفترة ويُتخذ العداد الحالي نقطة أساس جديدة. القيم المفقودة لا تتحول إلى صفر.

يُضمّن سجل القراءات في النسخ الاحتياطية الجديدة ويُدمج عند الاستعادة. ترقية المخطط من 4 إلى 5 تنشئ جدولاً جديداً ولا تحذف أي جدول أو سجل سابق.

**ملاحظة قياس:** RX+TX هو مجموع الحركة في اتجاهي الاستقبال والإرسال على واجهة VLAN؛ قد لا يساوي حركة User Manager أو استهلاك باقات ADSL بسبب اختلاف نقطة القياس، والتوجيه، والـ bridge، والتوقيت. لا تجمع الواجهات الأم والفرعية معاً باعتبارها حركة عملاء مستقلة، لأن ذلك قد يكرر البايتات. شاشة الفيلانات تجمع فقط واجهات VLAN المعرفة بأرقام 1–6، لكنها لا تستنتج تلقائياً أن أسماء VLAN الستة القديمة تطابق فعلياً مواقع العملاء؛ يجب مطابقة رقم VLAN واسم الواجهة على الراوتر قبل اعتماد التقارير.
